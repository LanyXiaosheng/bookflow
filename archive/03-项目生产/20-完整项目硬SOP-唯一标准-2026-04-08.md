## 2. 唯一文件标准

### 2.1 立项骨架五件套

`已立项` 的唯一门槛固定为：

1. `00-项目说明.md`
2. `02-大纲.md`
3. `03-10章细纲.md`
4. `04-爆点节奏表.md`
5. `07-标题简介AB版.md`

说明：

- `01-正文.md` 不计入立项门槛
- 任何“先做 `00-03`”口径一律废止

### 2.2 主生产闭环

一个项目进入可发布生产，主闭环固定为：

1. `00-项目说明.md`
2. `01-正文.md`
3. `02-大纲.md`
4. `03-10章细纲.md`
5. `04-爆点节奏表.md`
6. `05-发布版.md`
7. `06-发布配套.md`
8. `07-标题简介AB版.md`
9. `08-前30%试读优化.md`
10. `09-前30%精修版.md`
11. `10-平台发布完整稿.md`

### 2.3 完整项目 13 件套

如果目标不是“能发”，而是“完整项目封板”，则继续补齐：

12. `11-章节断点发布版.md`
13. `12-长篇版-约1万字.md`

结论：

- `00-10` 是主生产闭环
- `11` 和 `12` 是完整项目封板必备件
- `11` 与 `12` 职责不同，不是互相替代关系

---

## 3. 槽位语义锁定

核心槽位只认下面语义：

| 槽位 | 唯一标准名 | 固定语义 |
| --- | --- | --- |
| `04` | `04-爆点节奏表.md` | 爆点设计、节奏控制、情绪曲线 |
| `07` | `07-标题简介AB版.md` | 标题与简介 A/B 方案 |
| `11` | `11-章节断点发布版.md` | 分章断点连载底稿 |
| `12` | `12-长篇版-约1万字.md` | 长篇扩展成稿 |

硬规则：

- 新项目禁止在 `04 / 07 / 11 / 12` 槽位写入其他主文件名
- 同一槽位只允许一个主文件
- 如果需要额外增强文档，从 `13-*` 往后加，不许复用核心槽位

---

## 4. 状态机唯一标准

项目状态只由“文件存在性”触发，不接受备注式流转。

| 状态 | 唯一门槛 |
| --- | --- |
| `题目池` | 只有题目，未建项目目录 |
| `已立项` | 已补 `00 / 02 / 03 / 04 / 07` |
| `正文中` | `已立项 + 01` |
| `试读优化中` | `正文中 + 08 / 09` |
| `待发布` | `正文中 + 05 + 06 + 08 + 09 + 10` |
| `完整项目` | `待发布 + 11 + 12` |
| `已发布` | `待发布` 或 `完整项目` + 已回写 `03-项目生产/05-项目复盘表.md` |

补充：

- `12-长篇版-约1万字.md` 不是 `待发布` 门槛
- `12-长篇版-约1万字.md` 是 `完整项目` 门槛
- `可发` 若继续使用，等价于 `待发布`

## 5. 历史兼容映射

存量项目只做“读取兼容”，不做全量重命名搬迁。

| 历史文件名 | 兼容语义 | 处理规则 |
| --- | --- | --- |
| `04-模板应用说明.md` | 遗留增强文档 | 不计入 `04` 主槽位 |
| `07-长篇版-约1万字.md` / `07-长篇版-约2万字.md` | 长篇扩展稿 | 兼容映射到 `12` 语义 |
| `11-平台简介与标签.md` | 发布辅助资产 | 归并到 `06-发布配套.md` 语义 |
| `11-章节拆分发布版.md` | 章节连载底稿 | 兼容映射到 `11` 语义 |
| `12-分章节发布版.md` | 章节发布变体 | 兼容映射到 `11` 语义 |
| `12-章节断点发布版.md` | 章节断点变体 | 兼容映射到 `11` 语义 |

原则：

- 兼容映射只用于读取、统计、审计
- 新项目禁止继续写入这些历史名占用核心槽位

## 6. 禁止事项

以下写法从现在开始一律禁用：

1. `先做 00-03`
2. `04-模板应用说明.md` 作为 `04` 主文件
3. `07-长篇版-*` 继续占 `07` 主槽位
4. `11-平台简介与标签.md` 继续占 `11` 主槽位
5. 把 `12-长篇版-约1万字.md` 当成 `待发布 / 已发布` 硬门槛
6. 用“备注已补”“口头完成”代替文件门槛

## 7. 内容丰富度硬闸门

从 `正文中` 开始，所有项目都必须同时满足下面 5 条，否则不算合格推进：

1. 核心情节不允许从 `A` 直接跳到 `B`  
   `02 / 03 / 01 / 08 / 09 / 10 / 12` 里的关键转折，至少写清 `铺垫 -> 过程 -> 余波`
2. `03-10章细纲.md` 每章必须有新增量  
   至少推进 `冲突 / 关系 / 线索 / 隐患` 其中一项，纯复述不算有效章节
3. `04-爆点节奏表.md` 不只列爆点名词  
   必须同时写明 `紧场 / 松场 / 前30%卡点 / 反转位 / 情绪回本 / 兑现点`
4. 日常场景不能写成流水账  
   `01 / 08 / 09 / 10 / 12` 里的轻场景，至少承担 `关系升温 / 情绪缓冲 / 伏笔埋设 / 角色反差 / 下一冲突预热` 之一
5. 环境描写必须服务人物和剧情  
   脱离人物视角看风景、重复堆“伤心/温柔/压抑”等空词、没有情节功能的纯景段，直接判水

补充判断：

- 丰富 = 增层次，不是增字数
- 每次扩写，至少新增 `信息 / 阻力 / 情绪变化 / 关系变化 / 伏笔 / 余波` 中的一项

---

## 8. 主 Agent 监督规则

以后任何 agent 跑项目生产，主 agent 必须监督这 10 件事：

1. 是否先判定当前目标是 `立项`、`待发布`，还是 `完整项目`
2. 是否按状态门槛落文件，而不是按备注写状态
3. 是否误用历史命名写入新项目
4. 是否出现同槽位多主文件并存
5. 是否把 `11` 与 `12` 混成一个语义
6. 是否出现关键情节 `只报结果、不写过程`
7. 是否遗漏事件余波，导致桥段写完即丢
8. 是否出现无功能日常、空景描写、重复情绪词
9. 是否节奏连续过快或连续过慢，没有松紧交替
10. 是否在完成后回写复盘和状态表
