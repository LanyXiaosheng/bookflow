## 2. 当前立项标准冲突点

### 冲突 A：立项最小集合不一致（`00-03` vs `00/02/03/04/07`）

- `03-项目生产/03-跨赛道批量立项沟通模板.md` 多处定义“只立项 = `00-03`”。
- `00-目录导航.md`、`13-项目化生产流程.md`、`03-项目生产/03-批量立项清单.md` 定义“立项骨架 = `00/02/03/04/07`，正文后置”。
- 抽样项目说明中又存在“立项四件套 = `00/01/02/03`”表述。

影响：

- 同一个“已立项”状态，执行者可能按三种不同标准落盘，阶段状态失真。

### 冲突 B：同一编号槽位语义漂移（尤其 `04`、`07`、`11`、`12`）

- 新标准文档中：
  - `04` = `04-爆点节奏表.md`
  - `07` = `07-标题简介AB版.md`
  - `11` = `11-平台简介与标签.md`
  - `12` = `12-分章节发布版.md`
- 实际项目目录中广泛存在：
  - `04-模板应用说明.md`
  - `07-长篇版-约1万字.md`
  - `11-章节断点发布版.md`
  - 其他 `12-*` 非标准变体

影响：

- 编号已不能稳定表达阶段含义，自动巡检、排产统计、状态判断都会误判。

### 冲突 C：状态词与验收标准未绑定

- `03-项目生产/04-周排产表.md` 定义了状态流转：`题目池 -> 已立项 -> 正文中 -> 试读优化中 -> 待发布 -> 已发布`。
- 但未给出每个状态的“必备文件验收门槛”。

影响：

- `03-项目生产/03-批量立项清单.md` 中“已立项/正文中/可发”依赖人工口径，难以一致执行。

## 3. 冲突源头文件定位

### 一级冲突源（必须先修）

1. `03-项目生产/03-跨赛道批量立项沟通模板.md`
原因：它是实际发指令模板，仍大量输出 `00-03` 与 `04-模板应用说明.md` 的旧流程。

2. `项目-*/00-项目说明.md` 中“当前阶段目标”模板段（批量历史残留）
原因：大量项目将“立项”写成 `00/01/02/03`，与当前主 SOP 不一致。

### 二级冲突源（应同步修）

1. `03-项目生产/03-批量立项清单.md`
原因：虽定义了新骨架动作，但状态语义没有验收绑定。

2. `03-项目生产/04-周排产表.md`
原因：仅有状态名，无文件门槛定义。

### 相对稳定源（建议作为基线）

1. `00-目录导航.md`
2. `04-完整链路SOP.md`
3. `13-项目化生产流程.md`

这三份已基本一致地表达了“先骨架后正文”的新路径。

## 4. 建议的唯一立项标准（最小文件集合 + 状态定义）

## 4.1 唯一“立项最小集合”

建议统一为：

1. `00-项目说明.md`
2. `02-大纲.md`
3. `03-10章细纲.md`
4. `04-爆点节奏表.md`
5. `07-标题简介AB版.md`

解释：

- 与当前主 SOP/导航保持一致；
- 保证“立项”即具备结构、节奏、标题三层可执行性；
- 将 `01-正文.md` 明确后置到“正文中”。

## 4.2 状态验收门槛（建议固化到排产与清单）

- `题目池`：选题存在，未建项目目录
- `已立项`：满足上面 5 件套
- `正文中`：`已立项` + `01-正文.md`
- `试读优化中`：`正文中` + `08/09`
- `待发布`：`试读优化中` + `10-平台发布完整稿.md`
- `已发布`：`待发布` + 发布记录/复盘已回写（至少 `03-项目生产/05-项目复盘表.md` 有对应条目）

## 5. 历史文件修复分级（哪些可暂不追溯，哪些必须先修）

## 5.1 必须先修（影响后续持续执行）

1. 所有“对外发指令模板”中的旧口径（`00-03`、`04-模板应用说明` 等）
2. 所有“项目状态表”中缺失验收门槛的定义
3. 新增项目使用的模板文本（防止继续写入旧标准）

## 5.2 可暂不追溯（不阻断当前执行）

1. 历史项目目录内旧命名文件不强制重命名（如 `07-长篇版-约1万字.md`）
2. 历史项目说明中的叙述性内容不全面返工

前提：

- 在状态看板中按“新标准验收”判断，不再按旧文案判断。
- 必要时通过映射规则兼容历史命名，避免大规模搬迁。
