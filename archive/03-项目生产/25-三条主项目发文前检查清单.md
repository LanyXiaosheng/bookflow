# 三条主项目发文前检查清单

## 用途

发文前不要靠脑子记。

每次发三条主项目里的任意一篇，都先按这张清单过一遍。

---

## 一、通用检查

发文前先确认：

- [ ] 今天只发这一篇主项目，不双开
- [ ] 发文时间已确定
- [ ] 本篇顺位没乱
- [ ] 上一篇的 `T+1 / T+3 / T+5` 观察没漏
- [ ] 使用的文件版本已确定

---

## 二、文件检查

### 最少要确认的文件

- [ ] `05-发布版.md`
- [ ] `06-发布配套.md`
- [ ] `07-标题简介AB版.md`

### 如果要走完整版

- [ ] `10-平台发布完整稿.md`

### 如果要临时改开头

- [ ] 只在 `08` 或 `09` 里取，不要临时重写新版本

---

## 三、标题检查

发前过这四条：

- [ ] 事件场清楚
- [ ] 被逼失位清楚
- [ ] 翻盘物件清楚
- [ ] 标题不和当前库里高密度题族撞车

如果有一条说不清，就不要临时发。

---

## 四、简介检查

- [ ] 简介里能看出主冲突
- [ ] 简介里能看出女主不是被动挨打
- [ ] 简介里至少提到一个硬物件
- [ ] 简介没写成概括总结腔

---

## 五、项目专属检查

## 1. 股权代持

发前再确认：

- [ ] 主标题仍优先用 `敲钟上市那天...股权代持协议`
- [ ] 开头仍从 `高台失位` 起，不要换成前情回忆
- [ ] 证据物件必须先是 `股权代持协议`

## 2. 婚房账户

发前再确认：

- [ ] 主标题仍优先用 `婚房解押那天...共同账户`
- [ ] 开头必须从 `银行解押现场` 起
- [ ] 第一炸必须是 `账户冻结`

## 3. 赈灾银入库

发前再确认：

- [ ] 主标题仍优先用 `赈灾银入库那夜...火漆封条...御前`
- [ ] 开头必须从 `银库入夜 + 逼按手印` 起
- [ ] 第一炸必须是 `火漆封条 / 开库验封`

---

## 六、发后动作

发完不要立刻乱判断，只做三件事：

- [ ] 记下实际发文时间
- [ ] 在总控台账里补上发文日
- [ ] 预约自己在 `T+1 / T+3 / T+5` 看后台

---

## 七、最后一句

发文前最怕的不是版本不够多。

最怕的是：

- 顺位乱了
- 版本拿错
- 观察漏了

这张清单只要照着勾，就够了。
