# Findings

## 2026-05-05 Addendum

### F14. `守丹客` 这个账号名更适合窄而硬的 `古风志怪悬疑`，不适合一开始混甜宠或纯火葬场

已确认事实：

- `守丹客` 这个名字天然带有 `道门 / 炼丹 / 守秘 / 异闻` 气质
- 当前工作区此前没有一条明确的 `古风志怪悬疑` 赛道，只能拆散挂在 `悬疑反转` 或 `男频多元破界` 下面

结论：

- 如果直接拿 `守丹客` 做现言或纯甜宠，笔名和内容预期会错位
- 更合理的做法是先新增独立赛道，让账号气质和题材卖点先对齐

### F15. `我替死囚炼最后一炉丹，开炉的人却是三年前的我` 最适合做 `守丹客` 首发样板

已确认事实：

- 这条题同时具备：
  - `死囚临刑`
  - `最后一炉丹`
  - `三年前的我`
  三个强钩子
- 它既能立住 `守丹客` 的丹案气质，又符合短故事的异常开局和旧案翻回结构

结论：

- 这条题比泛县衙悬疑更能先打出账号识别度
- 后续第二条再接 `师父死后，我才知道他炼的不是丹，是命`，更容易形成连续感

## Confirmed Findings

### F1. 立项最低产物定义发生漂移

- `00-目录导航.md` 将立项骨架定义为 `00 / 02 / 03 / 04 / 07`
- `03-项目生产/03-批量立项清单.md` 的“本轮统一立项动作”也使用 `00 / 02 / 03 / 04 / 07`
- 多个项目目录下的 `00-项目说明.md` 却写成“立项四件套：00 / 01 / 02 / 03”

结论：

- “立项”到底包含正文首稿 `01-正文.md`，当前规则不一致
- 这会导致同一个阶段被不同执行者理解为不同落盘要求

### F2. 项目文件命名标准发生漂移

已观察到以下并行命名体系同时存在：

- `04-爆点节奏表.md`
- `04-模板应用说明.md`
- `07-标题简介AB版.md`
- `07-长篇版-约1万字.md`
- `11-平台简介与标签.md`
- `11-章节断点发布版.md`
- `12-分章节发布版.md`
- `12-长篇版-约1万字.md`

结论：

- 当前仓库同时混用了“骨架文件”“发布文件”“长篇扩展文件”的编号位
- 这不是单个项目漏文件，而是标准层已经漂移

### F3. 部分项目目录按“已立项”理解，但缺少当前骨架标准文件

抽样巡检显示，多数低完成度目录缺：

- `04-爆点节奏表.md`
- `07-标题简介AB版.md`

这与当前主导航、项目化流程中声明的立项骨架不一致。

### F4. SOP 文档之间存在代际冲突

- `04-完整链路SOP.md` 和 `13-项目化生产流程.md` 倾向使用较新的骨架/发布命名
- 多个历史项目说明、执行清单、沟通模板仍沿用旧命名

结论：

- 问题不是“忘了做某一步”，而是“不同入口文档仍在向执行者发出冲突指令”

## Working Hypothesis

当前所谓“sop 存储 bug”，更准确地说是：

1. 立项阶段定义不唯一
2. 文件编号槽位被不同版本流程复用了
3. 导航文档与项目模板没有同步重构

因此优先修的是“标准源”，不是盲目给所有旧项目补文件。

### F5. 高完成度项目存在稳定主流簇

基于 `*.md >= 13` 的高完成度项目全量聚类：

- 样本量：`40`
- `00/01/02/03/05/06/08/09/10` 在 `40/40` 项目中全部存在
- `11-章节断点发布版.md` 出现 `35/40`
- `04-爆点节奏表.md` 与 `07-标题简介AB版.md` 各出现 `33/40`
- `12-长篇版-约1万字.md` 出现 `30/40`

结论：

- “完整项目”主流稳定簇应定义为 13 件套
- 其中 `11=章节断点发布版`、`12=长篇版-约1万字` 比 `11=平台简介与标签`、`12=分章节发布版` 更接近真实生产主流

### F6. 应分离“待发布”与“完整项目”

来自完整样板和高完成度聚类的共同结论：

- `00-10` 构成主生产闭环
- `11` 与 `12` 是完整项目封板层
- `12-长篇版-约1万字.md` 不应作为 `待发布/已发布` 的硬门槛
- 但它应作为“完整项目”判定的一部分
