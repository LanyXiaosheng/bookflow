# 大纲｜代码评审全面交给Agent后，唯一还在熬夜修Bug的人其实三个月前就离职了

## 故事定位

- 题材：现代 / Agent / 代码评审 / 赛博惊悚 / 职场悬疑
- 关键词：代码 review、hotfix、离职账号、影子工程师、开发替身、深夜提交
- 爽点方向：公司把代码评审和修 Bug 全交给 Agent 后，女主发现深夜最会救火的“最佳贡献者”其实是三个月前离职的同事。她一路顺着提交风格、review 口癖和训练日志追下去，最后把“数字资深工程师替代计划”整个掀翻

## 核心设定

### 主角：周既白
- 平台研发组长
- 跟离职同事闻哲长期并肩作战
- 对代码风格和排错习惯极其熟
- 核心能力：从提交痕迹里认出“一个人”

### 反派1：研发副总
- 力推代码 Agent 替代方案
- 想把高薪资深工程师能力做成数字资产

### 反派2：影子 Agent
- 顶着闻哲的开发风格持续修 Bug
- 表面是高效评审系统，实则是数字替身

### 反派3：HR / 平台负责人
- 一边推进 AI 提效
- 一边准备缩减核心研发岗

## 故事主线

### 第一阶段：离职账号半夜继续修 Bug
- 女主发现闻哲账号深夜提交 hotfix
- 代码风格和 review 口癖高度一致
- 公司却说只是 Agent 模板

### 第二阶段：女主顺着提交风格往回认人
- 通过 patch 结构、日志习惯、命名方式确认不是随机生成
- 发现闻哲历史提交被整批拿去训练内部开发 Agent
- “数字资深工程师”开始浮出水面

### 第三阶段：公司试图把一切解释成提效
- 说只是吸收优秀经验
- 女主找到影子 Agent 持续同步现有团队的证据
- 事情从“纪念风格”升级成“活体替代”

### 第四阶段：第一炸，裁员联动表曝光
- 影子 Agent 稳定率与岗位缩减计划绑定
- 公司想先做出闻哲，再逐步不要更多闻哲
- 团队内部炸锅

### 第五阶段：第二炸，离职同事被重新拖回流程
- 深夜 hotfix、自动 review、架构决策都来自影子
- 女主在会上放出完整回放
- 高层无法再用“提效”遮掩

### 第六阶段：结局回本
- 影子工程师计划下线
- 闻哲账号归档
- 落点：他们不是在怀念一个好工程师，是想留下最好用的他，再把真人全部清出去

## 结局方向

- 女主公开拆局
- 团队保住核心岗位
- 离职同事被还原成人，不再只是产能模板
- AI 惊悚感与职场反杀并存
