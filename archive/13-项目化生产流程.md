# 项目化生产流程

## 为什么要项目化

只停在一篇改写稿，后面会马上遇到 6 个问题：

1. 正文和大纲脱节
2. 试读 30% 没单独优化
3. 平台发布时还得临时补标题、简介、标签
4. 长版、发布版、分章节版混在一起，不方便继续改
5. 题目很疯，但中段节奏容易泄掉
6. 批量生产时看不出哪个项目该优先推进

所以以后只要一篇稿子值得继续做，就必须走项目化生产。

如果是主 / 子 agent 并行推进：

- 主 agent 负责拆任务、审稿、验收和最终整合
- `01 / 10 / 12` 同一时刻只允许一个子 agent 独占写

## 标准项目化链路

### 第 1 步：先拿到种子稿
来源可以是：

- 外部短文
- 对标爆款
- 你自己脑洞
- 拆解后的非抄袭改写稿
- 疯题池里评分通过的题

输出：

- 一个能成立的核心故事

### 第 2 步：先补项目骨架
正文不是第一步，先把骨架搭起来。

优先补：

- `00-项目说明.md`
- `02-大纲.md`
- `03-10章细纲.md`
- `04-爆点节奏表.md`
- `07-标题简介AB版.md`

要求：

- 先把故事主线钉死
- 先把每章钩子钉死
- 先把前 30% 的起爆点钉死
- 先把标题和简介备好，不等发布前临时补
- 每个核心情节先拆成 `铺垫 -> 过程 -> 余波`
- 每章至少写出 `目标 / 阻碍 / 变化 / 章尾钩子`
- 这一步统一定义为 `已立项`
- `01-正文.md` 进入下一步再补，不算立项骨架

### 第 3 步：拉出正文首稿
再写 `01-正文.md`

要求：

- 不要只写梗概
- 必须有可读正文
- 至少完成一个完整冲突闭环
- 开头必须直接起爆，不允许慢热铺垫
- 每章至少新增 `2` 个变化点  
  一个是事件推进，一个来自 `关系 / 认知 / 规则` 变化
- 每场戏开写前先回答：`这场戏改变了什么`
- 每场戏至少有 `目标 / 阻力 / 代价`，否则容易写成流水账
- 写完后必须再过一次 `去 AI 味儿` 检查  
  重点检查：解释句过多、情绪空词过多、人物说话同质化、现场感不足

### 第 4 步：单独处理试读区
如果平台有试读比例，必须单独做：

- `08-前30%试读优化.md`
- `09-前30%精修版.md`

要求：

- 前 30% 不是铺垫区
- 必须是起爆区
- 必须卡在强悬念上
- 必须让读者读到这就想往下点
- 必须出现 `强冲突 / 意外信息 / 高代价选择` 各至少 `1` 处
- 必须按“番茄短篇赛马”思路倒推  
  重点不是“写完整”，而是“这 3000 字能不能扛住冷启动”
- 必须额外去一次 AI 味儿  
  因为试读区最怕像“合格总结稿”，不怕狠，就怕太顺太平太会概括

补充执行：

- 第一屏必须直接给主冲突或主证据
- 前 `500` 字必须让读者知道这篇最值钱的刀是什么
- 前 `1000` 字必须完成第一炸
- 前 `3000` 字必须卡在更大证据、反转或公开翻脸入口

### 第 5 步：整理平台完整稿
补：

- `10-平台发布完整稿.md`

要求：

- 前 30% 用精修后的结构
- 后续接完整闭环
- 口吻统一
- 这是平台可发的主终稿
- 不把 `10` 和 `12` 混成一个文件语义
- 写前至少判断一遍“读者为什么读”  
  如果只能靠开头炸点，说明平台稿也还不够稳
- 写前同时判断：  
  `这本如果只拿到一小口冷启动流量，为什么能继续晋级？`
- 写完必须自查一遍“去 AI 味儿”  
  平台稿不是提纲扩写，不允许大段总结、概括式转折和模板腔对话

平台向补充：

- 标题和简介必须服务点击率，不只是顺口
- 中段必须持续给新信息，避免完读率塌掉
- 每章结尾尽量留续读按钮，避免追读和书架下滑

### 第 6 步：整理章节断点发布版
补：

- `11-章节断点发布版.md`

要求：

- 章节短
- 章尾有钩子
- 方便平台连载
- 每章末尾尽量留“下一章不点开就亏”的信息差或反转前摇

### 第 7 步：整理长篇扩展稿
补：

- `12-长篇版-约1万字.md`

要求：

- 只在目标是 `完整项目` 时补
- 写前先补一份“读者为什么读”
- 答不出“为什么能继续读到 3000 / 6000 / 1w 字”，就不要强拉长稿
- 长不是重复，要靠 `铺垫 / 过程 / 余波 / 节奏松紧` 把内容撑开
- 哪些桥段能扩、哪些桥段一扩就泄，必须先判断
- 长稿越长越容易冒 AI 味儿  
  所以每扩一段都要防：
  - 同一类情绪反复说
  - 解释句越写越多
  - 人物全变成讲剧情的人
  - 段落节奏过于整齐

### 第 8 步：补平台配套
补：

- `06-发布配套.md`

要求：

- 标题备选
- 开头备选
- 简介
- 标签
- 题材归类
- 主推标题默认 `<25` 字，长标题放补充组
- 标签按 `主分类 / 情节 / 角色 / 情绪 / 背景` 五层输出
- 情节标签优先使用平台现成口径；具体事件词单独写进 `补充关键词`
- 角色标签优先使用平台现成口径；具体关系位单独写进 `补充关键词`
- 情绪标签优先使用平台现成口径；更细的情绪回本词写进 `补充关键词` 或卖点提炼
- 背景标签优先使用平台现成口径；更细的场域词写进 `补充关键词`
- 同一条书优先保 `1` 个主分类，再补 `2-4` 个情节标签，不要胡乱堆满

### 第 9 步：历史长稿兼容

如果历史项目已经存在单独长篇版：

- 保留旧文件，不强制回滚
- 历史 `07-长篇版-*` 兼容映射到 `12` 语义
- 后续以 `12-长篇版-约1万字.md` 作为长稿主维护文件

### 第 10 步：发布后复盘
每发一个项目，都回写：

- `03-项目生产/05-项目复盘表.md`

至少记录：

- 题目最能打的点
- 试读区最值钱的爆点
- 中段哪里拖
- 标题 A/B 哪个更好用
- 下次同类题怎么改

## 新的标准项目文件

一个进入生产状态的项目，建议按下面顺序补齐：

1. `00-项目说明.md`
2. `01-正文.md`
3. `02-大纲.md`
4. `03-10章细纲.md`
5. `04-爆点节奏表.md`
6. `05-发布版.md`
7. `06-发布配套.md`
8. `07-标题简介AB版.md`
9. `08-前30%试读优化.md`
10. `09-前30%精修版.md`
11. `10-平台发布完整稿.md`
12. `11-章节断点发布版.md`
13. `12-长篇版-约1万字.md`

## 项目完成标准

一个故事项目至少要有：

1. 项目说明
2. 大纲
3. 10 章细纲
4. 爆点节奏表
5. 标题简介 AB 版
6. 正文首稿
7. 试读优化
8. 平台完整稿
9. 章节断点发布稿
10. 平台配套
11. 约 `1w` 字长篇扩展稿（目标是 `完整项目` 时）

缺 3 项以上，就不算真正进入稳定生产状态。

补充验收：

- `01 / 09 / 10 / 12` 任何一项如果明显像总结稿、模板稿、说明文，即使文件齐全也不算合格

## 当前批量执行原则

以后新稿默认按下面规则推进：

1. 先从疯题池拿题
2. 先评分，再决定立项
3. 先补立项骨架 `00 / 02 / 03 / 04 / 07`，不急着全写正文
4. 同一批优先跑 3 到 5 个项目骨架
5. 再从里边挑 1 到 2 个强题进入正文和试读优化

也就是说：

`先批量搭骨架，再重点打正文。`

## 番茄短篇推荐机制接入

这里按两层理解：

### 已验证公开事实

1. 平台是明显的数据分发逻辑，不是编辑慢审逻辑
2. 点击、停留、完读、互动、追读会直接影响后续流量
3. 短篇活动、保底和激励口径会变，当期金额看官方活动页

### `[unverified]` 实战经验线

1. 新稿通常存在 `3小时 / 24小时 / 72小时` 的短窗口观察
2. 冷启动量小，淘汰快，前 3 天决定大部分后续流量
3. 常见参考线：
   - 点击率尽量 `>=15%`
   - 前 `3000` 字停留尽量 `>=40%`
   - 完读率尽量 `>=60%`
   - 追读率 / 书架率尽量往 `>=35%` 靠

使用方式：

- 不把这些经验线写成“官方死规则”
- 但所有 `07 / 08 / 09 / 10 / 11` 都按这套倒推
