# Fanqie Short Traffic

这份 reference 不是讲“怎么把稿子写完整”，而是讲：

`怎么按番茄短篇的推荐逻辑，把稿子写成更容易拿到继续加量的形态。`

## 证据边界

下面信息分两层使用：

### 已验证公开信息

1. 番茄存在明显的数据驱动分发和反刷量治理。  
   可从平台公开公告、创作者活动页和治理公告确认。
2. 发布后是否继续给量，和点击、停留、完读、互动、追读、转化这类数据强相关。  
   官方短故事数据模块已公开“展现量”“阅读量”等分析维度，并明确展现量会受作品推荐后的数据反馈等因素影响。
3. 平台对短篇和超短篇存在专项激励、保底和短剧联动扶持，但活动口径会变。  
   活动金额、周期、参加门槛以当期官方页面为准。

### `[unverified]` 运营经验线

下面这些属于创作者实战经验阈值，不按“官方硬规则”引用，只按“执行参考线”使用：

- `3小时 / 24小时 / 72小时` 三段观察
- 初始小流量测试后按数据继续放量
- 点击率、前3000字停留率、完读率、互动率、书架率、追读率是最关键的晋级指标
- 冷启动窗口短，前 3 天决定大部分后续流量

如果后续拿到番茄后台更具体的数据面板，再优先用后台口径替换这份经验线。

## 一句话理解平台机制

番茄短篇不是“先给足流量，再慢慢看表现”，而是：

`先给一小口流量试跑，再按数据逐级赛马，只放大明显更能留人的稿子。`

## 内容生产必须服务的 6 个核心指标

按内容侧重要性排序：

1. 点击率  
   由标题、封面感、题材词、第一屏承诺共同决定。
2. 前3000字停留 / 开篇留存  
   决定稿子能不能活过冷启动。
3. 全文完读率  
   决定能不能持续加量。
4. 互动率  
   评论、点赞、分享、催更、书架。
5. 追读率 / 书架率  
   尤其影响继续放量和连载向判断。
6. 阅读时长  
   单用户停留越久，平台越容易判断内容“吃得住流量”。

## 用内容去打平台赛马的固定思路

### 1. 点击率靠“标题承诺明确”

标题不要只疯，要让读者一眼明白：

- 谁最惨
- 谁最狠
- 当场发生什么
- 反杀证据是什么

标题错误写法：

- 只写情绪，不写事件
- 只写身份，不写冲突
- 只写重生，不写第一刀

标题正确写法：

- `时间点 + 羞辱场 + 核心证据 / 核心动作`
- 让读者一眼就知道“点进去能看什么”

标题长度补充：

- 主发标题默认控制在 `25` 字以内
- 如果长标题才能讲清完整事件，长版放进备选，主推位仍优先短标题
- 短标题优先保：
  - 时间点
  - 核心羞辱
  - 反击动作

### 2. 前3000字靠“第一屏起爆”

前 3000 字不是交代区，是冷启动生死区。

必须尽量做到：

1. 第一屏直接给冲突，不给背景铺垫
2. 前 500 字让读者知道这篇最值钱的刀是什么
3. 前 1000 字必须完成第一炸
4. 前 3000 字至少完成：
   - 1 次明确反击
   - 1 个更大的真相入口
   - 1 个强卡点

### 3. 完读率靠“中段不断加新信息”

中段最容易掉速。

平台不怕你狠，怕你重复。

中段必须持续给：

- 新证据
- 新阻力
- 新代价
- 新身份位变化
- 新关系裂缝

不能只靠：

- 重复吵架
- 重复委屈
- 重复解释前因后果

### 4. 互动率靠“读者想说话”

最容易出评论的不是平顺剧情，而是：

- 很气人的现实羞辱
- 明显站边时刻
- 强价值判断
- 女主终于不忍 / 男主终于翻车
- 结尾留一口“你会不会原谅 / 该不该原谅”的讨论位

### 5. 追读率和书架率靠“章尾要卡，不要平”

每章结尾尽量落在下面几类点上：

- 刚掀出一半证据
- 对方刚意识到事情不对
- 主角刚做出更狠的决定
- 下一步要去更公开的场合反杀
- 真相只差最后一页没翻开

### 6. 阅读时长靠“紧一下、松一下、再上钩子”

不是全程短句，也不是全程大段说明。

要让读者有阅读呼吸：

- 爽点短
- 转折短
- 余波稍长
- 证据说明短切
- 日常段也必须带功能

## `[unverified]` 实战参考线

下面阈值只作为内容生产参考，不写成平台官方明文：

### 冷启动观察

- `3小时`：先看标题点击和前段停留
- `24小时`：再看前几章完读、评论、书架
- `72小时`：基本能看出这条题是否还会继续被放量

### 内容目标线

- 点击率：`>=15%` 及格，`>=20%` 更稳
- 前3000字停留：`>=40%` 才有继续跑的机会
- 完读率：短篇尽量 `>=60%`
- 书架率 / 追读率：尽量往 `>=35%` 靠
- 互动率：评论、点赞、分享总和尽量 `>=1%`

这些线不是平台公开红线，但能指导我们怎么写 `08 / 09 / 10`。

## 平台机制倒推到文件层的执行要求

### `07-标题简介AB版.md`

至少输出：

- `2` 组主标题
- `2-3` 组简介
- 每组都要明确题材词、冲突词、证据词
- 主推标题尽量 `<25` 字
- 如果有长标题版本，放进补充组，不占主推位

### `08-前30%试读优化.md`

必须回答：

1. 第一屏炸点是什么
2. 前 500 字读者为什么不停
3. 前 1000 字第一炸落在哪
4. 前 3000 字卡点落在哪
5. 这段最容易掉留存的地方在哪里

### `09-前30%精修版.md`

必须做到：

- 直接可投平台试读区
- 少解释，多现场
- 不允许前 3000 字还在铺关系背景

### `10-平台发布完整稿.md`

必须自查：

1. 前段是否真按 `09` 的结构起爆
2. 中段有没有重复冲突
3. 章尾有没有继续读按钮
4. 是否存在会拖完读的解释段

### `06-发布配套.md`

必须补：

- 题材标签
- 主推标题组
- 补充标题组
- 简介 AB 版
- 卖点提炼
- 一句话推荐语

## 标签处理规则

番茄标签不是装饰，而是分发入口。

标签乱，系统就把书推给不对的人。

### 五层标签框架

每次出书，优先按下面 5 层去配：

1. 主分类
2. 情节
3. 角色
4. 情绪
5. 背景

### 1. 主分类

主分类只定大盘，不要贪多。

常见可选方向：

- 婚姻家庭

- 男生生活

- 虐心婚恋
- 青春虐恋
- 男生情感

- 悬疑
- 悬疑惊悚
- 玄幻仙侠
- 宫斗宅斗

- 女频衍生

- 古风世情

- 不要把主分类写成情节词

### 主分类选择捷径

- 现言离婚、隐婚、白月光、追妻火葬场：优先 `虐心婚恋`

- 现言偏甜、先婚后爱、双向奔赴：优先 `现言甜宠`
- 古言嫡庶、王府、侯府、内宅争斗：优先 `宫斗宅斗`
- 古言先婚后爱、替嫁后甜线更强：优先 `古言甜宠`
- 古言情感拉扯、和离、追悔、虐恋：优先 `古言虐恋`
- 四合院、家属院、进厂、分房、津贴：优先 `年代`
- 军阵、守城、降书、粮道、古代男频翻盘：优先 `历史古代`

  这些更适合放进 `情节标签`

## 标签选择顺序

每次出书，按下面顺序定：

1. 先定 `主分类`
2. 再定 `最强情节`
3. 再定 `核心角色`
4. 再定 `主情绪`
5. 最后补 `背景`

## 标签数量建议

默认建议：

- 主分类：`1`
- 情节：`2-4`
- 角色：`1-2`
- 情绪：`1-2`
- 背景：`1-2`

总量尽量控制在 `6-9` 个有效标签，不要把所有能想到的词都塞进去。

## 选标签的 4 个硬规则

1. 只选正文里真的打得响的标签  
   标题写了 `重生`，正文前段必须真有重生；别挂空标签。
2. 优先选点击词，不选解释词  
   例如优先 `离婚 / 重生 / 白月光 / 难产 / 追妻火葬场`，少选空泛描述。
3. 标签之间不要打架  
   例如主打虐渣反杀，就别同时堆太多偏轻甜的期待词。
4. 标签必须和标题、简介、前3000字一致  
   不一致会拖点击、留存和推荐匹配。

## 常见断流内容问题

1. 开头 1000 字还在交代婚龄、职业、相识过程
2. 第一炸来得太晚
3. 标题疯，正文不炸
4. 中段只会重复骂、重复哭、重复解释
5. 证据拿得太晚，读者中途掉光
6. 标签和题材不准，系统分发不到对的人
7. 结尾太平，没有回本感和讨论点
