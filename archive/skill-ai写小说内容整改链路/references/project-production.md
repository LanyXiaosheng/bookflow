# Project Production

当内容已经适合做成真实小说项目，或用户要求“直接开工生产小说”时，使用这份 reference。

## Goal

不要停在单篇改写稿。

把题目、故事种子或半成品项目升级成可继续推进、可进入平台发布链路的 `项目-题目/`。

## Task Modes

先按 `references/execution-matrix.md` 判断任务模式。

- `只立项`：最低骨架是 `00 / 02 / 03 / 04 / 07`
- `立项+平台发布链路`：再补 `01 / 05 / 06 / 08 / 09 / 10 / 11`
- `完整项目封板`：在平台发布链路基础上再补 `12`
- `只补缺口`：不重写稳定文件

## Minimum project structure

如果任务已经进入正文或完整发布阶段，最低必须有：

1. `00-项目说明.md`
2. `01-正文.md`
3. `02-大纲.md`
4. `03-10章细纲.md`

如果任务只是 `只立项`，不要把 `01-正文.md` 当成最低必需。

优先按同赛道最近项目对齐：

- `11-章节断点发布版.md`
- `11-平台简介与标签.md`

## Production logic

固定顺序：

1. 先确认题目是否值得做
2. 先钉一句话故事与赛道定位
3. 如果只是 `只立项`，先补 `00 / 02 / 03 / 04 / 07` 后停下
4. 如果进入平台发布链路或完整项目封板，先补 `00 / 02 / 03 / 04 / 07`
5. 再写 `01`
6. 再补 `05-10`
7. 进入 `08 / 09 / 10 / 11` 前，先按 `references/fanqie-short-traffic.md` 过一遍点击承诺、前3000字停留按钮、完读按钮和互动按钮
8. 准备写 `10` 或 `12` 前，先补“读者为什么读”判断
9. `10-平台发布完整稿.md` 作为平台可发主稿先落地
10. 再补 `11-章节断点发布版.md`
11. 如果目标是完整项目封板，再补 `12-长篇版-约1万字.md`
12. 最后更新 `03-下一步执行清单.md`

直接项目任务默认是执行，不是只讲方法。

并行执行时，主 / 子 agent 分工遵循 `references/execution-matrix.md`，尤其是正文、`10` 和历史 `12` 的独占写规则。

## Quality bar

项目未达到下面标准，不算进入稳定生产状态：

- 有核心可读正文
- 有章节结构
- 有试读区优化
- 有平台完整稿或发布版
- 有标题、简介、配套支持
- 前 30% 有强卡点
- 标题承诺、前3000字留存按钮和章尾续读按钮明确
- `10` 和 `12` 语义不混用
- 做约 `1w` 字长稿时，能明确说清读者为什么会读到中后段
- `01 / 10 / 12` 没有写成只有事件经过的流水账
- 与同赛道项目风格一致
