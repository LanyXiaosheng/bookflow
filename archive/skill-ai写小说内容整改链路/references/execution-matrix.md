# Execution Matrix

当任务已经不是“看素材”，而是要真正落地项目时，先看这份矩阵。

## 先解析这 7 个字段

如果用户提供了结构化任务，先抽出：

1. `任务类型`
2. `题目` 或 `赛道分配`
3. `赛道`
4. `选题来源`
5. `执行要求`
6. `主 agent / 子 agent` 分工
7. `是否要求反流水账精修 / 多维丰富`

缺字段时再补推断，不要先改写用户任务。

## 任务模式矩阵

### 1. 只立项

最低产物固定为：

1. `00-项目说明.md`
2. `02-大纲.md`
3. `03-10章细纲.md`
4. `04-爆点节奏表.md`
5. `07-标题简介AB版.md`

规则：

- `01-正文.md` 不是只立项最低产物
- 不要顺手补 `05-11`
- 如果项目目录已经存在旧文件，不删除，只补本轮应有缺口

### 2. 立项 + 平台发布链路

最低应补到：

1. `00-项目说明.md`
2. `01-正文.md`
3. `02-大纲.md`
4. `03-10章细纲.md`
5. `04-爆点节奏表.md`
6. `05-发布版.md`
7. `06-发布配套.md`
8. `07-标题简介AB版.md`
9. `08-前30%试读优化.md`
10. `09-前30%精修版.md`
11. `10-平台发布完整稿.md`
12. `11-章节断点发布版.md` 或同义旧编号

附加规则：

- 写 `10` 前，先确认前 30% 已起爆，不要带着慢热稿进平台稿
- `10-平台发布完整稿.md` 是平台可发主稿，不和 `12` 混用
- 如果用户沿用旧说法 `立项+完整发布链路`，默认按这一档执行

### 3. 完整项目封板

在 `立项 + 平台发布链路` 基础上，再补：

13. `12-长篇版-约1万字.md`

附加规则：

- 写 `12` 前先补一份“读者为什么读”
- `12` 是长篇扩展稿，不是 `10` 的兼容别名
- 如果历史项目 `10` 和 `12` 并存，`10` 视为平台整理稿，`12` 视为长稿源文件
- 如果答不出“读者为什么能继续读到 3000 / 6000 / 1w 字”，就不要强拉 `12`

### 4. 只补项目缺口

规则：

- 只补用户要求或项目当前缺失的槽位
- 不重写已经稳定的文件
- 先读同目录已有文件，再补后续链路

### 5. 批量跑

规则：

- 一项目一 worker
- 共享文件只允许一个 agent 写，或由主 agent 最后统一改
- 不允许两个 worker 同时改 `03-下一步执行清单.md` 或同一赛道项目清单

## 主 / 子 Agent 协议

用户明确要求主 / 子 agent 时，按下面执行：

### 主 agent

- 负责解析任务
- 负责文件所有权划分
- 负责去重审查
- 负责共享文件最终整合
- 负责反流水账验收，不负责大面积正文落稿

### 子 agent

- 只改分配给自己的文件
- 不越权改其他项目目录
- 不回滚既有内容
- `10` 或历史 `12` 必须指定一个正文落稿子 agent 独占写
- 完成后只汇报：改了什么、去重点、残留风险

### 模型规则

- 用户明确要求 subagent 执行时，默认使用 `gpt-5.4`
- 如果用户额外限制模型，只按用户限制执行

## 去重审查清单

新项目立项前，至少过这 4 层：

1. 角色：主角身份、亲属关系、男主职位是否重复
2. 场景：公开翻脸场、递材料场、家属院场、探亲夜场是否重复
3. 证据：账本、批文、监控、遗嘱、脉案等核心证据是否重复
4. 结尾：公开站边、迟来后悔、规则反打、身份翻盘是否重复

## 赛道前置

进入任何赛道项目前，至少读：

1. 对应赛道 `00-赛道总纲.md`
2. 对应赛道的 `03-读者为什么读.md` 或等价文件
3. 对应赛道 `02-项目清单.md`

## 硬规则

- 先补骨架，再补正文
- 先补试读，再写平台稿或长稿
- 共享文件最后改
- 不要把“只立项”偷偷做成“半个完整发布链路”
- 写 `01 / 10 / 12` 前，必须先明确 `一句话故事 / 主角目标 / 核心冲突 / 关键反转 / 结局方向`
- 验收 `10 / 12` 时，至少检查 `前30%是否起爆 / 中段是否有持续推进线 / 章尾是否有钩子 / 是否重复吵架或换说法拖字数`

## 汇报格式

对用户的阶段性汇报和最终收口，统一按下面 4 段组织：

1. `判断`
2. `执行`
3. `验证`
4. `后续`
