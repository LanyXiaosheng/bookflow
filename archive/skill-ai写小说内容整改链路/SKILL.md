# AI写小说总控链路

这个 skill 只服务当前工作区：`AI写小说`。

目标不是“看完资料”或“只写一篇”，而是把输入推进到：

`拆解判断 -> 非抄袭改写 -> 可复用资产 -> 疯题判断 -> 项目化生产 -> 试读优化 -> 平台发布 -> 下一步执行`

并且保证最终文本：

- 不写成流水账
- 不只报结果，能补出过程和余波
- 不只堆冲突，能写出氛围与节奏
- 不为凑字数而重复争吵、重复解释、重复情绪

## 适用场景

当任务属于下面任一情况时启用：

- 处理新的抖音链接、图文、文章、课程笔记
- 拆解 AI写小说 对标账号或案例
- 从素材中提炼选题、脚本、提示词、SOP
- 把某条内容改写成可直接使用的新结果
- 把某个故事种子升级为项目文件夹或发布稿
- 用户直接要求“启动整个项目”“立项开写”“补齐项目目录”“继续生产小说”
- 更新当前目录的导航、执行清单或方法沉淀

## 不处理的范围

不要把这个 skill 用到：

- 泛 AI 工具收集
- 与小说创作无关的自媒体选题
- 单纯资讯摘要
- 只做摘录、不产出结果的整理任务

## 结构化入口

如果用户按下面这种结构发任务，优先按字段执行，不要自行改写用户意图：

- `任务类型`
- `题目` 或 `赛道分配`
- `赛道`
- `选题来源`
- `执行要求`
- `主 agent / 子 agent` 分工
- `是否要求反流水账精修 / 多维丰富`

常见触发词包括：

- `开始执行完整流程`
- `主 agent 负责监督审查，子 agent 负责实际执行`
- `别写成流水账`
- `去AI味`
- `去 AI 味`
- `别写得像AI`
- `不要像AI总结稿`
- `把情节、氛围、节奏一起拉满`
- `任务类型：只立项`
- `任务类型：立项+完整发布链路`
- `任务类型：完整项目封板`
- `选题来源：我直接给你题目`
- `选题来源：从现有选题库里挑`
- `执行要求：按默认模板严格执行`

## 固定执行顺序

1. 先判断任务属于哪条子流程
2. 再按子流程读取对应 references
3. 如果内容有项目潜力，不停在拆解层，直接升到项目目录
4. 如果任务已经是项目生产，不要只给方案，直接创建或补齐文件
5. 若任务改变当前推进状态，顺手更新 `03-下一步执行清单.md`

## 核心规则

- 新素材不能只保存原始链接或原文，必须产出整理结果
- 无法直接打开源内容时，要分清“已确认事实”和“高可信推断”
- 优先提炼可复用方法，不要停留在表面复述
- 每条素材至少落地成一个可继续使用的 Markdown 文件
- 有项目潜力的内容，不要停在拆解层，要升级成项目文件夹
- 直接项目生产时，先按 `references/execution-matrix.md` 判断任务模式，再执行
- 只要进入约 `1w` 字的 `12-长篇版-约1万字.md`，必须明确“读者为什么会继续读”，不能只扩字数
- 涉及平台试读比例时，单独优化前段内容
- 只要进入 `07 / 08 / 09 / 10 / 11`，默认同时按 `references/fanqie-short-traffic.md` 检查点击承诺、前3000字停留、完读按钮和互动按钮
- 保持当前目录既有命名方式，不随意另起体系
- 新项目必须先过一次 `角色 / 场景 / 证据 / 结尾` 四层去重
- 如果用户明确要求主 / 子 agent，主 agent 只负责分工、审查、回收和反流水账验收；子 agent 负责写文件
- 如果用户明确要求用 subagent 执行，本 skill 下默认子 agent 使用 `gpt-5.4`，除非用户另行指定
- 对用户的阶段性汇报与最终交付，统一按 `判断 / 执行 / 验证 / 后续` 组织

## 反流水账硬规则

只要任务涉及 `01 / 08 / 09 / 10 / 12`，默认同时执行下面规则：

1. 关键转折不能只写结果，必须补 `铺垫 -> 过程 -> 余波`
2. `03-10章细纲.md` 每章至少写 `目标 / 阻碍 / 变化 / 章尾钩子`
3. 每场戏开写前，先回答一句：`这场戏改变了什么`
4. 每场戏至少有 `目标 / 阻力 / 代价` 三项，缺一项就容易空转
5. 每场戏至少留 `1` 个信息差和 `1` 个细节锚点
6. 日常场景至少承担 `关系升温 / 情绪缓冲 / 伏笔埋设 / 角色反差 / 下一冲突预热` 之一
7. 环境描写只准服务人物情绪或剧情压力，脱离人物看风景直接判水
8. 解释/交代型文字不得连续超过 `3` 段，连续 `2` 场都只交代信息也要重写

## 番茄赛马硬规则

只要任务涉及 `07 / 08 / 09 / 10 / 11`，默认同时执行下面规则：

1. 标题必须让读者一眼看懂：`谁最惨 / 当场发生什么 / 反杀刀是什么`
2. 主发标题默认压到 `25` 字以内，优先短、硬、能一眼读完
3. 前 `500` 字必须出现主冲突或主证据，不允许纯背景介绍
4. 前 `1000` 字必须完成第一炸，不允许慢热
5. 前 `3000` 字必须留下强卡点，最好落到新证据或更大反转入口
6. 中段必须持续加新信息，不允许只重复骂、重复哭、重复解释
7. 章尾必须留“继续读”按钮，不允许平收
8. `06-发布配套.md` 里必须给出标题 A/B 和标签，不允许只写一个孤立标题
8. 标签必须按 `主分类 / 情节 / 角色 / 情绪 / 背景` 五层去配，主分类优先使用番茄现成口径，不能只堆关键词

## 去 AI 味儿硬规则

只要任务涉及 `01 / 08 / 09 / 10 / 12`，默认同时执行下面规则：

1. 不把戏写成总结  
   能演出来的，不直接解释。

2. 不滥用抽象情绪词  
   少写“崩溃、愤怒、难过、委屈”，多写动作、反应、停顿、失控点。

3. 对话必须分人  
   每个角色至少要有自己的口气、词习惯、停顿方式和说狠话的方式。

4. 允许人物有毛边  
   允许嘴硬、失言、误判、装镇定、没说完，别把所有人都写得像高配嘴替。

5. 背景信息嵌进现场  
   不要整段讲设定、讲旧账、讲关系史，优先塞进动作、证据、对话和场面里。

6. 避免模板腔段落  
   如果连续几段句式太整齐、节奏太平均、每段都像“起承转合标准件”，就要重写。

## 最低交付标准

一次处理默认至少应包含：

1. 一句话判断
2. 核心内容拆解
3. 非抄袭改写
4. 可直接使用的输出结果
5. 可复用资产（选题 / 脚本 / 提示词 / SOP）
6. 项目化包装（如适用）
7. 发布配套（如适用）

如果任务是“只立项”，最低还应包含：

1. `项目-题目/`
2. `00-项目说明.md`
3. `02-大纲.md`
4. `03-10章细纲.md`
5. `04-爆点节奏表.md`
6. `07-标题简介AB版.md`

`01-正文.md` 不属于只立项最低产物，进入正文或完整发布链路后再补。

## 文件落点建议

按内容类型优先写入：

- 赛道总纲：`抖音内容拆解-AI写小说赛道.md`
- 单条案例：`抖音内容拆解-AI写小说-XX.md`
- 资产沉淀：`AI写小说-XX.md`
- 控制文件：`00-xx.md`、`01-xx.md`、`02-xx.md`、`03-xx.md`
- 项目文件夹：`项目-题目/`

项目生产常用文件：

- `04-爆点节奏表.md` 或 `04-模板应用说明.md`
- `05-发布版.md`
- `06-发布配套.md`
- `07-标题简介AB版.md`
- `08-前30%试读优化.md`
- `09-前30%精修版.md`
- `10-平台发布完整稿.md`
- `11-章节断点发布版.md`
- `12-长篇版-约1万字.md`
- `13-读者为什么读.md` 或后续编号的同类文件

兼容当前仓库差异：

- 有些项目用 `11-章节断点发布版.md`
- 有些项目用 `11-平台简介与标签.md`
- 历史项目可能保留 `07-长篇版-*`，读取时兼容到 `12-长篇版-约1万字.md`
- 有些项目会再补 `13-读者为什么读.md` 或 `14-前10章读者为什么读.md`
- 优先复用同赛道最近项目的编号方案，不强行统一旧项目

## 项目生产红线

- 不停在灵感、梗概、摘要
- 开头 1000 字内必须起爆
- 前 30% 必须是起爆区，不是铺垫区
- 标题和简介至少给 A/B 版
- 试读稿、发布稿、完整稿与正文主线必须一致
- `10-平台发布完整稿.md` 是平台可发主稿，不和 `12` 混用
- `12-长篇版-约1万字.md` 是完整项目封板层的长篇扩展稿
- 做约 `1w` 字长稿时，必须说明读者会因哪几个按钮继续读到后段
- 不机械同义词替换，不照搬现有项目句式
- 不允许出现只有事件经过、没有关系变化和余波的流水账正文
- 不允许出现明显“AI 总结稿腔”：结论句过多、解释句过多、人物同声同调、段落过度工整
- 直接项目任务默认是“执行”，不是“讲方法”

## 完成定义

只有当素材从“输入”变成下面至少一个结果时，才算完成：

- 可复用案例拆解
- 可直接发布或继续生产的改写稿
- 选题/脚本/提示词资产
- 小说项目文件夹
- 对当前工作区下一步有影响的状态更新

如果任务是“直接启动项目”，只有满足下面至少一项才算完成：

- 新建了完整可读的 `项目-题目/`
- 把半成品项目补到发布状态
- 把题目推进到试读优化或平台完整稿
- 更新了 `03-下一步执行清单.md` 并明确下一步轮转目标
