# AI写小说内容整改：完整链路 SOP

## 目标
把任何新进入目录的内容，统一走完下面这条链路：

`输入内容 -> 拆解判断 -> 非抄袭改写 -> 结果输出 -> 疯题筛选 -> 项目化生产 -> 试读优化 -> 平台发布 -> 复盘归档 -> 下一步执行`

最终结果不是“多了一篇笔记”，而是：

1. 多了一份可复用拆解
2. 多了一份非抄袭改写稿
3. 多了一个可直接使用的输出结果
4. 多了一个可持续迭代的项目目录
5. 多了一条明确的下一步动作
6. 多了一条能继续批量复制的爆款路径

补充边界：

`本链路只处理 AI写小说相关内容。`

如果新内容与 AI写小说弱相关，就不进入这条主链路。

---

## 完整链路

## 第 0 阶段：内容进入目录
输入内容可以是：

- 抖音链接
- 图文文章
- 课程笔记
- 对标账号视频
- 工具方法文章
- 你自己冒出来的疯题脑洞

前提：

- 必须与 AI写小说直接相关

进入目录后，不允许只收藏，必须进入处理链路。

---

## 第 1 阶段：内容识别
先判断它属于哪一类：

1. 赛道认知
2. 对标案例
3. 工具讨论
4. 创作方法
5. 流程实操
6. 提示词/脚本/选题素材
7. 可直接升级为项目的故事种子

输出：

- 内容类型
- 一句话判断
- 归档文件名

---

## 第 2 阶段：内容拆解
固定拆 6 件事：

1. 它本质在讲什么
2. 为什么值得拆
3. 开头怎么抓人
4. 中段怎么建立逻辑
5. 结尾怎么承接下一步
6. 背后的账号方法是什么

如果原文拿不到，必须分成：

- 可确认事实
- 高可信推断

---

## 第 3 阶段：非抄袭改写
每篇内容处理完，必须完成一轮非抄袭改写。

改写标准：

1. 不照搬原文句式
2. 不做机械同义词替换
3. 保留核心价值，重组表达逻辑
4. 形成新的可直接使用文本

---

## 第 4 阶段：结果输出
每篇内容必须产出一个最终结果。

可选结果包括：

1. 新的短篇开头
2. 新的故事梗概
3. 新的章节大纲
4. 新的提示词结果
5. 新的 AI写小说教学结果
6. 新的疯题候选

如果没有输出结果，就不算走完整链路。

---

## 第 5 阶段：疯题筛选
在进入项目目录前，先判断它是不是能打的题。

最少要补 8 个字段：

1. 标题
2. 赛道
3. 主角身份
4. 开局死局
5. 核心反杀动作
6. 最大读点
7. 短篇 / 中篇潜力
8. 开工指数

再按下面维度打分：

- 标题点击感
- 开局炸裂度
- 打脸清晰度
- 情绪强度
- 反转空间
- 30%试读卡点能力
- 连载延展性

建议规则：

- `28 分以上：立刻立项`
- `23-27 分：可备选`
- `22 分以下：先不做`

---

## 第 6 阶段：项目化生产
如果题目值得继续写，就不能停在单文件，必须进入项目目录。

立项阶段最低骨架固定为：

1. `00-项目说明.md`
2. `02-大纲.md`
3. `03-10章细纲.md`
4. `04-爆点节奏表.md`
5. `07-标题简介AB版.md`

补齐以上 5 项后，项目状态统一记为 `已立项`。

`01-正文.md` 不属于立项最低产物，进入正文阶段后再补。

进入项目目录后的完整结构建议：

1. `00-项目说明.md`
2. `01-正文.md`
3. `02-大纲.md`
4. `03-10章细纲.md`
5. `04-爆点节奏表.md`
6. `05-发布版.md`
7. `06-发布配套.md`
8. `07-标题简介AB版.md`

如果目标平台存在试读比例，还要继续补：

9. `08-前30%试读优化.md`
10. `09-前30%精修版.md`
11. `10-平台发布完整稿.md`
12. `11-章节断点发布版.md`
13. `12-长篇版-约1万字.md`（只在目标是 `完整项目` 时补）

也就是说：

`有潜力的稿子，不是存成一篇，而是升格成一个带爆点控制和发布预案的项目。`

如果是主 / 子 agent 并行推进：

- 主 agent 负责拆任务、审稿、验收和最终整合
- `01 / 10 / 12` 同一时刻只允许一个子 agent 独占写，避免长稿互相覆盖

---

## 第 7 阶段：爆点节奏控制与反流水账
每个项目在正文扩写前，先补：

- `04-爆点节奏表.md`

至少明确：

1. 第 1 章炸点
2. 第 3 章爆点
3. 第 5 章爆点
4. 第 8 章爆点
5. 第 10 章兑现点
6. 前 30% 卡点
7. 最大反转点
8. 结局回本点
9. 哪几章是紧场，哪几章是松场
10. 哪一段负责余波，哪一段负责下一轮预热

如果这一步没做，正文很容易前炸后泄。

进入正文、试读优化、长稿扩写前，再过下面 6 条：

1. 每个核心情节都要补足 `铺垫 -> 过程 -> 余波`
2. `03-10章细纲.md` 每章至少写清 `目标 / 阻碍 / 变化 / 章尾钩子`
3. `01-正文.md` 每章至少新增 `2` 个变化点  
   一个是事件推进，一个来自 `关系 / 认知 / 规则` 变化
4. 每场戏开写前，先能回答一句：`这场戏改变了什么`
5. 每场戏至少有 `目标 / 阻力 / 代价` 三项，缺一项就容易变成空场景
6. 每场戏至少留 `1` 个信息差和 `1` 个细节锚点，不要只写解释和概述

## 第 7.5 阶段：去 AI 味儿

只要任务涉及：

- `01-正文.md`
- `08-前30%试读优化.md`
- `09-前30%精修版.md`
- `10-平台发布完整稿.md`
- `12-长篇版-约1万字.md`

默认必须再过一轮 `去 AI 味儿` 检查。

### 什么叫 AI 味儿

不是指“用了 AI 写”，而是指文本读起来像：

1. 太会总结，不像人在现场
2. 情绪词很多，但动作和细节很空
3. 人物说话一个味，像同一个人轮流开口
4. 句子太整齐，段落太平均，转折太规矩
5. 太爱解释“她很难过 / 他很愤怒 / 这说明什么”，却没有具体反应
6. 明明是戏，却写成剧情介绍
7. 所有人都太聪明、太会说重点，缺少人的迟疑、卡壳、嘴硬和误判

### 去 AI 味儿硬规则

1. 少写结论句，多写现场反应  
   不直接说“她崩溃了”，优先写她手在抖、话断掉、东西拿不稳。

2. 少写万能情绪词，多写可见细节  
   `愤怒 / 难过 / 崩溃 / 委屈 / 心痛` 这类词能不用就不用，优先换成动作、表情、声音、停顿。

3. 对话不能都像会写稿的人  
   人物要允许嘴硬、说岔、反问、停住、不把话说满。

4. 不要把人物写成“功能块”  
   反派不能只会坏，主角不能只会硬，配角不能只负责递信息。

5. 少写整段解释，多写信息嵌入  
   背景、旧账、设定，尽量拆到动作、对话、证据和现场里，而不是整段交代。

6. 避免均匀排比和模板句连发  
   连续三段都用同一节奏、同一类句式，读起来就会很像模型模板。

7. 一场戏至少留一个“人的毛边”  
   可以是嘴瓢、误会、装镇定、没接住话、表里不一、下意识动作。

### 代入感强化补充规则

1. 用“我”的感受写“他”  
   即使是第三人称，也要让读者贴着主角在现场里受、疼、忍、慌、撑，不要站在外面总结“他很愤怒”“她很委屈”。  
   少写：`叶良辰感到很愤怒。`  
   多写：`血一下冲上头顶，他拳头攥得发紧，指骨咯吱一响。再忍一下，他怕自己真会当场掀桌。`

2. 五感优先于叙述  
   门推开时的热气、衣料擦过手背的触感、脚底踩到的异物、耳边听见的响动，优先让读者先感觉到，再知道发生了什么。  
   少写：`他走进了一个房间。`  
   多写：`门刚推开，暖气和甜腻香水味一起扑过来，地板上散着衣服，最上面那件粉色内搭，是他昨天才买的。`

3. 主角先普通，再逆袭  
   开局优先给工作、房贷、面子、家庭、身体、身份上的现实压力，先让读者觉得“这人跟我一样惨”，再给反杀。

4. 多造“如果是我”时刻  
   被抢功、被看不起、被公开比较、被伴侣冷待、被家里偏心、被规则卡死，这类现实屈辱和渴望最容易形成代入。

5. 对白必须像说话  
   允许短句、抢话、停顿、反问、嘴硬、话到嘴边又咽回去，别把人物写成会背台词的嘴替。

6. 节奏就是呼吸  
   爽点、揭穿、出手、翻盘，用短句。  
   余波、回忆、迟疑、情绪回落，用长句。  
   一场戏里要有收有放，不能从头到尾一个拍点。

### 去 AI 味儿自检清单

- [ ] 有没有连续三句都在解释人物感受，而没有动作承载
- [ ] 有没有大段“她知道 / 她明白 / 她终于意识到”式总结
- [ ] 有没有对话去掉人名后，谁说都一样
- [ ] 有没有反派张口就是标准坏人台词
- [ ] 有没有场景只推进信息，不留下人物反应
- [ ] 有没有句子过于工整，像口播稿或提纲扩写
- [ ] 有没有把本该演出来的戏，直接概括掉
- [ ] 第三人称是否贴住主角当下感受，而不是作者在外面解释
- [ ] 关键场景是否至少有一处五感落点
- [ ] 主角开局是否先露出普通人处境，而不是直接像超人
- [ ] 是否设计了让读者想“如果是我”的现实痛点或欲望
- [ ] 对话是否张嘴就像真人，而不是书面腔
- [ ] 爽点和紧张点是否用短句拉节奏，过渡是否适度放长

### 通过标准

去完 AI 味儿后，文本至少要做到：

1. 能看到人，不只看到剧情
2. 能听出谁在说话，不只看到台词
3. 能感觉到现场，不只知道发生了什么
4. 能留下余味，不只把信息交代完

## 第 8 阶段：平台发布
进入发布阶段后，必须补齐：

1. 平台完整稿
2. 章节断点发布版
3. 标题备选
4. 简介文案
5. 标签和题材归类

并且：

- 发布前必须先看 `07-标题简介AB版.md`
- 如果平台有试读比例，例如 `30%`，就必须单独优化前 30%
- 标签、简介、封面文案统一收纳在 `06-发布配套.md`
- `10-平台发布完整稿.md` 是平台可发的主终稿
- `11-章节断点发布版.md` 是连载拆章底稿
- `12-长篇版-约1万字.md` 是完整项目封板层的长篇扩展稿，不是 `10` 的别名
- `10` 和 `12` 在交付前都必须通过一次 `去 AI 味儿` 复查
- 准备写 `10` 或 `12` 前，必须先补一份“读者为什么读”判断  
  答不出“为什么能继续读到 3000 / 6000 / 1w 字”，就不要强拉长稿
- 只要进入 `07 / 08 / 09 / 10 / 11`，默认按“番茄短篇赛马”倒推  
  重点不是写得完整，而是写得更容易扛住冷启动

### 番茄短篇赛马执行规则

这里分两层：

#### 已验证公开事实

1. 平台明显按数据分发，不是靠人工慢审给量
2. 点击、停留、完读、互动、追读会直接影响后续流量
3. 活动激励、保底和短剧联动口径会变，当期以官方页面为准

#### `[unverified]` 实战阈值

下面阈值按运营经验使用，不按官方明文引用：

- `3小时 / 24小时 / 72小时` 是关键观察窗口
- 点击率尽量 `>=15%`
- 前 `3000` 字停留尽量 `>=40%`
- 全文完读尽量 `>=60%`
- 追读率 / 书架率尽量往 `>=35%` 靠

#### 文件层硬要求

1. `07-标题简介AB版.md` 至少给 `2` 组主标题和 `2-3` 组简介
2. 主推标题默认 `<25` 字，优先一眼读完
3. `08-前30%试读优化.md` 必须回答：
   - 第一屏炸点是什么
   - 前 `500` 字为什么不停
   - 前 `1000` 字第一炸落在哪
   - 前 `3000` 字卡点落在哪
4. `09-前30%精修版.md` 不允许前 `3000` 字还在铺背景
5. `10-平台发布完整稿.md` 必须自查中段是否重复冲突、结尾是否还有续读按钮
6. `11-章节断点发布版.md` 每章结尾尽量留信息差、证据差或公开翻脸前摇
7. `06-发布配套.md` 的标签必须按 `主分类 / 情节 / 角色 / 情绪 / 背景` 五层输出，不能只列散标签

## 历史命名兼容

历史项目如果出现以下文件名，按下面语义兼容读取：

- `04-模板应用说明.md` -> 视为遗留增强文档，不计入 `04` 主槽位
- `07-长篇版-*` -> 兼容映射到 `12-长篇版-约1万字.md` 语义
- `12-长篇版-约1万字.md` -> 继续保留为 `12` 语义
- `11-平台简介与标签.md` -> 兼容到 `06-发布配套.md` 语义
- `11-章节拆分发布版.md` / `12-分章节发布版.md` / `12-章节断点发布版.md` -> 兼容到 `11-章节断点发布版.md` 语义

## 第 9 阶段：复盘归档
每次发布后，至少回写：

1. 这个题最强的点是什么
2. 开头哪一刀最值钱
3. 哪段最拖
4. 标题 A/B 哪个更能打
5. 下次同类题该怎么改

复盘统一放进：

- `03-项目生产/05-项目复盘表.md`

---

## 第 10 阶段：更新下一步
最后更新：

- `03-下一步执行清单.md`

只记录 3 件事：

1. 新增了什么
2. 这次沉淀出了什么
3. 下一步最该做什么

---

## 完成标准
一篇内容只有满足下面条件才算处理完成：

1. 有归类
2. 有一句话判断
3. 有结构拆解
4. 有非抄袭改写
5. 有最终输出结果
6. 有疯题判断或立项判断
7. 有项目化产物
8. 有发布稿或发布准备
9. 有复盘入口
10. 有下一步动作
11. 正文和精修链路没有写成流水账

---

## 以后固定执行顺序
以后你每次打开这个目录，只按下面顺序看：

1. `00-目录导航.md`
2. `03-下一步执行清单.md`
3. `02-资产库/02-番茄短篇疯题立项池.md`
4. `03-项目生产/03-批量立项清单.md`
5. 值得继续的题，先补项目骨架
6. 再进入正文和试读优化

## 这套链路真正解决的问题
它解决的不是“怎么记更多笔记”，而是 6 个核心问题：

1. 防止内容只收藏不沉淀
2. 防止拆解完却没有改写结果
3. 防止题目看着疯，正文却不炸
4. 防止写出一篇后没有项目化生产
5. 防止批量项目推进时不知道先写哪个
6. 防止发布完没有复盘，下一轮还在重复踩坑
